先搞懂几个名词（大白话版）

💡 看不懂下面任何一个词，先读这里

ETF（交易型开放式指数基金）
简单说就是「一篮子股票打包成的一只基金」，在股票软件里像买卖股票一样买卖。比如「半导体ETF」就是一篮子半导体公司的集合。本系统买卖的就是这类基金，不直接买单只股票。
量化交易
用程序按固定规则自动下单，不靠人盯盘。本系统就是「程序在固定时间点自动决定买卖」。
AI 决策
系统把「当前行情 + 研报 + 你的持仓」整理成一段文字发给 AI（DeepSeek），AI 回一段「买哪只、买多少、卖哪只」的文字，程序再照着下单。
QMT（国金证券的量化终端）
一个安装在你电脑上的软件，是程序和券商「下单通道」之间的桥。程序不能直接连券商，必须先开 QMT 并登录。
miniQMT（极简版 QMT）
QMT 有两种打开方式：完整版（有图表界面）和极简版（XtMiniQmt.exe）。本系统只能用极简版，因为只有通过它，外部程序才能发指令。
API Key（钥匙）
调用 AI 时需要的一串密码，格式像 sk-xxxxxx。没有它，AI 不让你用。
Python
一种编程语言。本系统是一堆 Python 代码，需要电脑上装好 Python 3.11 才能运行。
模拟交易 vs 实盘
模拟 = 用假钱演练，亏了不心疼；实盘 = 真金白银。系统默认模拟交易，确认稳妥后再切实盘。
集合竞价
每天 09:15–09:25，大家把买卖意向挂上去，09:25 统一撮合成开盘价。这个时段下单有特别规则（只能用「限价单」），本系统已经处理好。
研报
券商/机构出的行业分析报告，告诉哪些板块最近有资金关注。系统会把研报喂给 AI 当参考。

系统整体长什么样

一句话：每天固定的 4 个时间点，程序自动读行情+读研报，问 AI 该怎么操作，然后自动下单。

研报

+
QMT 行情
拉实时价格
→

→
QMT 自动下单

用生活化的比喻：

  • 研报 = 晨报/情报（告诉你今天哪些行业有消息）
  • QMT 行情 = 眼睛（实时看到价格涨跌）
  • AI = 大脑（综合情报+价格，决定买什么卖什么）
  • QMT 下单 = 手（真正把单子提交到券商）
关键事实：本系统默认是模拟交易（假钱，初始 100 万），不会动你的真实资金。你确认 AI 决策靠谱后，再改成实盘。

1安装 Python 和依赖

如果显示 Python 3.11.x 就没问题。如果没装或版本不对：

  • 推荐装 Anaconda（自带 3.11，安装时一路下一步即可）
  • 或去 python.org 下载 3.11 版本（安装时务必勾选「Add Python to PATH」）
本机已有 Anaconda 的 Python 3.11.4，路径是 D:\software\anaconda3\python.exe。后面所有命令都用这个完整路径，避免和别处的 Python 弄混。

1.2 安装项目依赖

在命令行里，先进入项目目录，再装依赖：

cd D:\策略\etf_trading_system

2申请 AI 的「钥匙」——DeepSeek API Key

本系统支持三种 AI 后端（通过 config/settings.py 的 LLM_PROVIDER 切换，也可设环境变量）：
  • deepseek（默认）= DeepSeek 官方接口，模型 deepseek-reasoner（R1 推理模型），环境变量 DEEPSEEK_API_KEY
  • aliyun = 阿里云百炼（DASHSCOPE_API_KEY，保留，支持联网搜索）
  • tencent = 腾讯云（TENCENT_DEEPSEEK_API_KEY，保留）
三种后端的代码全部保留，不删，只通过开关切换。对新手，用默认的 DeepSeek 官方接口就行，下面只讲这一种怎么申请。

2.1 注册并拿到 Key

  1. 打开 platform.deepseek.com，用手机号注册登录
  2. 左侧「API keys」→ 点「Create API Key」
  3. 复制生成的 Key（格式 sk-xxxxxxxx），马上存到记事本，因为它只显示一次
  4. 点「Top up」充值，充 10 元就够测试很久（每次调用几分钱）
务必先充值！余额是 0 时，AI 会返回 402 Insufficient Balance，系统就无法决策。

2.2 把 Key 填进配置

用记事本打开 D:\策略\etf_trading_system\.env，把 DEEPSEEK_API_KEY 的值换成刚才复制的 sk-xxx。详见第 4 步的 .env 模板。

3安装并登录国金证券 QMT

3.1 下载安装

  1. 在国金证券开户，并申请开通 QMT / miniQMT 量化权限（联系你的客户经理或客服）
  2. 下载 QMT 量化交易终端，装到默认目录（常见如 D:\国金证券QMT交易端\ 或 D:\国金QMT交易端模拟\）
  3. 安装完，目录里会有 bin.x64\Lib\site-packages\xtquant，这就是程序要用的配件

3.2 两种模式，记住只用一个

模式启动程序外部程序能连吗
完整版XtItClient.exe❌ 不开放
极简版（miniQMT）XtMiniQmt.exe✅ 开放接口
必须用极简版（XtMiniQmt.exe）！程序是通过 xtquant 连 QMT 的，完整版不开放这个接口，开着完整版会报「QMT连接失败」。

3.3 启动并登录极简版

  1. 先关闭任何已打开的完整版 QMT
  2. 找到并双击 你的QMT目录\bin.x64\XtMiniQmt.exe（例如 D:\国金QMT交易端模拟\bin.x64\XtMiniQmt.exe）
  3. 输入资金账号和密码登录
  4. 登录成功后，QMT 会自动创建 userdata_mini 文件夹——这就是程序要连的目录
原理：miniQMT 像「中间人」。你的 Python 程序 → 发指令给 miniQMT → miniQMT 转发给券商。所以 miniQMT 必须先开着并登录，程序才能工作。关掉它，程序就断线。

4填写配置文件 .env

用记事本打开 D:\策略\etf_trading_system\.env，按下面模板填（只改有「填这里」字样的值，其余保持原样）：

# ===== AI 后端开关：deepseek(官方,默认) / aliyun(百炼) / tencent(腾讯云) =====
LLM_PROVIDER=deepseek

# DeepSeek 官方 Key（默认后端，必填）—— 填这里
DEEPSEEK_API_KEY=sk-你刚复制的DeepSeek钥匙

# 下面两个一般不用动（aliyun / tencent 后端才用）
DASHSCOPE_API_KEY=你的阿里云Key
TENCENT_DEEPSEEK_API_KEY=你的腾讯云Key

# QMT 配置
QMT_PATH=D:\国金QMT交易端模拟\userdata_mini   # ← 改成你实际的 userdata_mini 路径
QMT_ACCOUNT=你的资金账号                      # ← 填你的 QMT 账号（测试用 888888）
QMT_SESSION_ID=123456

各字段一句话说明

字段说明示例
LLM_PROVIDER用哪个 AI，默认 deepseekdeepseek
DEEPSEEK_API_KEYAI 钥匙（第 2 步拿的）sk-xxx
QMT_PATHminiQMT 的 userdata_mini 目录（不是安装目录本身）D:\国金QMT交易端模拟\userdata_mini
QMT_ACCOUNT你的 QMT 资金账号888888（测试）
QMT_SESSION_ID随便填个数字123456
QMT_PATH 怎么确定？这个路径指向 miniQMT 登录后自动生成的 userdata_mini 目录。不是 QMT 安装目录，也不是 userdata 目录。登录成功后它才会出现。

5研报是怎么来的（你不用管，系统自己搞）

AI 做决策需要「行业研报」当参考。这件事系统会自动完成，你不用手动搜：

  1. 主来源：开盘前自动预爬。程序在每天 08:30（盘前） 和 12:30（午后） 自动调用 findtruman 的结构化行业研报接口，生成当天研报文件存到 logs/research/。这样 09:25 一开盘就有研报可用，不依赖外部定时器是否成功。
  2. 补充：若你配置了 WorkBuddy 研报定时器（09:00 / 12:45 生成），它的文件内容更丰富，会被优先采用；否则就用上面自动预爬的。
  3. 兜底：都没拿到，AI 就在「无研报上下文」下决策，不会卡住交易。

研报 → ETF 自动映射（新功能）

研报里写的是「半导体」「券商」「军工」这类行业词，但程序下单要的是具体 ETF 代码。系统会自动扫描研报，把行业词映射到 ETF_POOL 里的具体基金，并标注情绪（利好/利空），然后把这段「映射」追加进喂给 AI 的研报里，帮 AI 更精准地下单。

✅ 这套机制意味着：你完全不用碰研报。开盘前它会自动准备好，并自动翻译成 AI 能用的 ETF 列表。

四个新功能，专门讲给小白听

① M1 集合竞价限价单（为什么重要）

每天第一笔决策在 09:25，正好是集合竞价时段。这个时段柜台只收「限价单」（你指定一个价格），不收「市价单」（随行就市）。之前系统在第一笔用了市价单，是某天「废单」的次要原因之一。

现在怎么处理：系统识别到是 09:25 或竞价时段，会自动把所有买卖转成限价单挂入开盘竞价。价格取 AI 给的目标价；AI 没给就用「当前价 ±0.2%」争取成交，并限制在 ±10% 内防止被拒。你不需要做任何设置。

② 策略净值 / 收益评估（看自己赚没赚）

想知道这段时间 AI 到底帮你赚了多少？有个专门模块，从真实成交记录重建你的资产曲线，并和「沪深300ETF」基准对比。

# 评估全部历史（自动判断能否连 QMT / 用缓存 / 用演示数据）
D:\software\anaconda3\python.exe strategy/evaluator.py

# 只看最近 30 天
D:\software\anaconda3\python.exe strategy/evaluator.py --days 30

# 强制用演示数据（离线验证，结果无实盘意义）
D:\software\anaconda3\python.exe strategy/evaluator.py --mode demo

跑完生成：

⑤ 多轮 prompt 传递（让 AI 记得自己前面干了啥）

这是很多新手最容易忽略、但最影响真实收益的一点。

AI 每次被调用都是「失忆」的——它不知道自己 09:25 下了什么单、10:30 成交了没有、有没有废单。如果 10:30 / 12:50 / 14:30 的 prompt 里不带前面的结果，AI 就等于每次从零开始瞎猜，可能重复下单、或对一个已经废单的指令反复纠结。

现在怎么处理：系统会自动从磁盘读取今天所有更早时刻的 logs/decisions/*.json（里面同时存了 AI 的决策和真实执行结果），拼成一份「前序执行回顾」文本块，注入到每一个后续时刻的 prompt 里：

  • 10:30 的 prompt → 带上 09:25 的真实执行（买了啥 / 成交✅ / 挂单🔵 / 未成交❌ / 跳过⏭️）
  • 12:50 的 prompt → 带上 09:25 + 10:30 两次
  • 14:30 的 prompt → 带上 09:25 + 10:30 + 12:50 三次
为什么读磁盘而不是读内存？因为程序可能被你手动分段跑（比如 --test all 一个一个来），或中途重启过。读磁盘能保证不管怎么跑、重启几次，前面时刻的上下文都不丢。而且只取当天的记录，不会把上周的尘封日志翻出来。

AI 决策长什么样（不用懂，看着玩）

AI 返回的是一段「结构化文字」（JSON），程序直接解析它来下单。你看个大概意思就行：

{
    "buy_orders": [
        {
            "etf_code": "512480.SH",   // 买哪只（半导体ETF）
            "action": "开盘买入",
            "position_ratio": 0.35,    // 占总资金 35%
            "stop_loss": -0.08,        // 跌 8% 止损
            "reason": "半导体板块资金流入明显"
        }
    ],
    "sell_orders": [ ... ],             // 卖哪只、减多少
    "overnight_position_plan": { "target_ratio": 0.5 }  // 过夜留 50% 仓位
}

出错了怎么办（排错指南）

首选排错工具：一键自检脚本。遇到「连不上 / 废单 / 不知道账号登没登录」，先跑它： 
D:\software\anaconda3\python.exe diagnose_qmt.py
它会依次：① 连接 QMT → ② 查账户资金/持仓（任何时段都能验证账号是否登录）→ ③ 交易时段内下 1 笔极小测试单 → ④ 明确告诉你「通道正常 / 废单 / 账号没登录」。比瞎猜快得多。
Q: 启动后显示「QMT连接失败」？
1. 确认开的是 miniQMT（XtMiniQmt.exe）不是完整版；2. 确认已登录；3. 确认 .env 的 QMT_PATH 指向 userdata_mini；4. 确认账号填对。仍不行就跑 diagnose_qmt.py。
Q: 显示「API调用失败: 402 Insufficient Balance」？
DeepSeek 余额不足，去 platform.deepseek.com 充值几块钱。
Q: 显示「ModuleNotFoundError: No module named 'xtquant'」？
xtquant 找不到。检查 trading/qmt_client.py 顶部的路径列表是否指向你 QMT 实际的 bin.x64\Lib\site-packages。它在 QMT 安装目录里，pip 装不了。
Q: 程序一直「等待交易时刻...」不动？
正常！只在周一到周五的 09:25/10:30/12:50/14:30 触发。想立刻验证用 python main.py --test moment_1。
Q: 必须用 Anaconda 的 Python 吗？
不一定，但必须是 Python 3.11 或更低。因为 xtquant 只支持 3.6~3.11。3.12+ 会报错。Anaconda 自带 3.11，所以推荐。
Q: 买入/卖出显示「废单」？
废单 = 本地拿到了序号、但券商柜台实际没记录。最常见根因：QMT 交易账号没在客户端登录（行情连接 ≠ 交易连接）。跑 diagnose_qmt.py，看它第 ② 步「账户资金」能否查到——查不到就是账号没登录；查到了还废单，多半是账号不属于当前 QMT 环境。解决：打开 XtMiniQmt.exe 在客户端里登录交易账号。
Q: 模拟交易和实盘的区别？
settings.py 里 QMT_SIMULATE = True 表示模拟（假钱，100 万）。实际是否走真实通道，看你登录 QMT 用的是模拟还是真实账号。建议先用模拟账号测试，确认 AI 决策合理后再考虑实盘（改 QMT_SIMULATE = False）。
Q: 能在手机上运行吗？
不能。依赖 QMT 终端和 Python，只能在 Windows 电脑上跑。

公众号自动发文（草稿箱模式）

交易日 15:30，WorkBuddy 自动化会基于当日日报+研报，自动生成一篇「ETF 每日复盘」文章，上传到你的公众号草稿箱。

为什么是「草稿箱」不是「直接群发」？个人/未认证订阅号没有群发接口权限（会返回 48001）。草稿箱接口对所有号开放，所以自动化只负责「写稿+上传草稿」，群发需你登录 mp.weixin.qq.com 后台手动点「发表」。要彻底自动群发需认证公众号。
真实性校验：自动化第 0 步会检查今日是否有真实决策。若当天只跑过 --test 预演、无真实决策，会自动暂停发文，避免把演练当真实复盘发出去。
